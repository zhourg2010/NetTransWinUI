# 交付件没有画、而程序绕不开的界面

`FlashgetMini` 交付件画了 23 屏，是完整的高保真设计。但它每一屏都是"东西
已经在里面"的状态：任务列表是满的，种子是载入好的。真实程序还有一批**空
状态和前置状态**，交付件从未画过——它们不是设计缺陷，是原型天然照顾不到的
地方。

这份文件记下这些屏，以及它们各自照着交付件的哪套语言做的。规则是：**不发
明新的视觉语言**，只用交付件已有的 token、控件和版式。

---

## 1. 主窗 · 第一次打开（队列为空）

**交付件的空态是筛选后为空**（一行 `.fnote` 的「没有符合条件的任务」），
不是首次启动。照搬那一行的结果是一个灰色空框，而那是所有人看到的第一眼。

| 元素 | 取自 |
|---|---|
| 72px 蓝色圆角方块，圆角 16 | 交付件 HTML 里的 app 标记（`rx=22/100` 换算） |
| 方块内的下载图标 | 同上：`M50 32v26m0 0l-10-10m10 10l10-10M32 70h36`，100 viewBox 换算到 24，笔画比 0.055 |
| 标题 17px / 600 | iOS 分组空态的标准字号（交付件唯一没给的值） |
| 副行 | `.fnote`（12.5px / `--label2`） |
| 按钮 | `.big`（sheet 的主操作样式，蓝底圆角 12） |

两种空态**分开**：`HasNoTasks` 走这一屏，`IsFilteredEmpty` 保留交付件原本
那一行。

## 2. 种子 sheet · 载入之前

交付件只画了载入之后的「种子内容」。粘磁力链、选种子文件这个前置状态是程序
必须有的，用 `.frow` 表单行实现，和载入后共处一个 sheet：有内容时
`ContentsSection` 显现。

## 3. 设置 · 「网络」组

交付件的设置只有 **下载 / 队列与计划 / 行为** 三组，没有代理这一行。代理是
程序的功能，单开一组 `网络`，不塞进"队列与计划"（和排队、计划都不沾边）。

## 4. 新建菜单 · 两个工具项

交付件的新建菜单是 4 项。程序多了「深度整理…」「大文件核对…」两个工具，用
交付件的分隔线（`.ctx hr`）与下载类分开。

## 落地时和交付件不一致、且**有意为之**的地方

这些是目标平台逼出来的，不是疏忽。每一条都要能说清为什么。

| 位置 | 交付件 | 程序 | 原因 |
|---|---|---|---|
| 下拉框高度 | `padding:4px 8px` 撑出 25 | 显式 `Height="25"` | WinUI 在模板内部把下拉框下限钉在 32，样式属性、合并字典、主题字典三条路都够不着 |
| 「完成」徽章圆角 | `border-radius:20px` | `9.5` | CSS 会把过大的圆角夹到边长一半，WinUI 不会，20 会画成透镜形 |
| 行盒高度 | `line-height:normal` | 写死 `LineHeight` | Segoe 的行盒和交付件渲染用的字体不同；写死才能得到交付件那个 62px 的行 |
| 字体 | SF Pro / Inter Tight | Segoe UI Variable / 微软雅黑 | 目标机器上没有那两个字体 |
| 毛玻璃 | `backdrop-filter: blur()` | 半透明纯色 | WinUI 没有 backdrop-filter |

## 给以后的自己

**控件写好了不等于用上了。** `CheckRow` 的注释里点名说它是给「种子内容」用
的，写完之后那个 sheet 一直在用 WinUI 原生 CheckBox——因为没有人把那一屏
渲染出来看过。

现在有 `--screens`：程序自己走 24 屏、逐屏出 PNG，CI 每次推送都跑，Release
挂原图和联系表。**任何"改好了"的说法，都要有那一屏的图为证。**
